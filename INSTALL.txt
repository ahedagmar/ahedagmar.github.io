V17 — INSTALLATION (one-time migration)
1. Back up the current repository (GitHub > Code > Download ZIP).
2. Upload index.html, script.js, style.css, collection-index.json and content/settings.json to their same paths in the repository. Do not delete original content files. The ZIP also contains .pages.yml; do not apply this until step 5. Do not upload migrate-v17.html or INSTALL.txt unless desired.
3. Open migrate-v17.html locally. Select the existing content/projects.json, content/news.json, content/notebook.json from your backup. Download the migration ZIP and extract it.
4. Upload the generated content folder to the repository root. It creates individual records under content/projects/, content/news/, content/notebook/ and a collections-ready.json activation marker. Keep the old JSON arrays as backup. The generated collection-index.json requires GitHub Pages' Jekyll build (Settings > Pages > Deploy from a branch; no .nojekyll file). Check the online collection-index.json is valid JSON and lists all migrated records before editing in CMS. If it is not, do not switch CMS yet. Remove collections-ready.json to revert to the original arrays.
5. Paste .pages.yml into Pages CMS Configuration and save. The CMS collections use title and year/date columns. Check the number of entries against migration report before editing.
6. New and edited records are picked up by the automatically generated index at each Pages deployment. The old arrays are backups, no longer edited by CMS. For subsequent updates do not re-run the migration.
Notes: static public repository means drafts and media may still be accessible by direct URL; not private storage. Video files must be browser-compatible (MP4/WebM). Image download deterrents do not prevent screenshots or direct retrieval. Individual project hash URLs retained. Social share cards, automatic image optimisation and authenticated preview are not implemented.
