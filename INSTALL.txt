V18 — ACTUALIZACIÓN SIN REEMPLAZAR CONTENIDOS
1. Descarga una copia de seguridad de tu repositorio (Code > Download ZIP).
2. Reemplaza SOLO index.html, script.js y style.css en la raíz.
   No borres content ni images. No reemplaces settings.json.
3. En Pages CMS > Configuration, usa UNA configuración de cms/:
   - pages-legacy.yml si todavía editas los proyectos como Item 1, Item 2.
     Mantiene tus listas existentes y añade el campo YouTube URL.
   - pages-collections.yml SOLO si ya migraste y comprobaste que todos
     tus proyectos, updates y notas aparecen como archivos independientes
     con el índice y el marcador de activación v17. Permite nombres, año,
     búsqueda y orden. No migres de nuevo ni cambies la estructura a ciegas.
   No subas los dos YAML al repositorio: copia el elegido a Configuration.
   Si aún ves Item 1, envíame el ZIP ACTUAL de GitHub para preparar una
   migración con tus datos reales. No hay que volver a introducirlos.
4. Opcional: instala tools/optimize_images.py y .github/workflows/optimize-images.yml
   en sus rutas exactas. Comprime imágenes nuevas en images/ al subirlas;
   también puedes ejecutar Optimize portfolio images manualmente desde Actions.
   GitHub Actions necesita permiso de escritura. Mantén los originales fuera
   de GitHub: comprime los archivos publicados (sin cambiar nombres).
   Conserva PNG/JPEG/WebP, no toca GIF animado, PDF ni vídeos. Límite 2400 px.
   La historia git conserva versiones originales; no libera ese espacio histórico.
   Si Pages usa un workflow propio, puede requerir volver a ejecutarlo después
   de la optimización; el workflow incluido solicita rebuild de Pages por rama
   pero no sustituye tu configuración actual de publicación.
5. YouTube URL acepta links normales, youtu.be, Shorts y Live. Se carga al pulsar
   Play video. Los videos antiguos siguen funcionando.
6. Si ya migraste a colecciones, conserva tu collection-index.json actual.
   Este paquete no modifica ni migra contenidos reales.
